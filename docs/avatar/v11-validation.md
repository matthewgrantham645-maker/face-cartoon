# 第十一版验证记录

基于 `c000913`（已合入风格管理、gzip 与较大图片结果支持）继续修改。没有改动千问接口模型或密钥配置，没有调用付费生图。验证使用本仓库原有插画和程序生成的窄眼棋盘背景测试图，摄像头回调使用固定关键点。

## 可观察到的改动

- 睁眼继续使用原图纹理，接近全睁的噪声归到中性。独立的闭眼补线只在接近闭眼时淡入。
- 口型幅度、眨眼响应、眼神幅度和侧脸幅度按图保存，并写入导出的 `.mavatar`。口型显示幅度与摄像头检测灵敏度独立。
- 表情按钮和循环检查复用正式渲染器；放大编辑器支持源图像素坐标、键盘、拖动、缩放、撤销和重做。未应用的几何改动会禁用角色导出，避免导出旧结果。
- 刷新后恢复上次成功应用的图库图片；摄像头短暂丢脸平滑回到中性；旧会话的延迟推理不会关闭新会话。

## 网格保护

原运动权重在人物边缘变化过快；在同一测试插画、侧脸幅度 0.6、组合转头/俯仰/歪头时，基础网格曾出现每帧 104–239 个翻折三角形。第十一版加入只向内收缩的距离羽化，背景零权重保持零，并按有向面积约束每帧位移。

`portrait_workbench_browser.test.js` 检查八组极端姿态，每帧基础网格 5,970 个三角形。修订后八组均为 **0 个翻折**，最小三角形面积约为原面积的 **26.5%**；本测试中的眼睛和上下唇图层也均为 0 个翻折。算法单元测试另外检查 1,000 组变化位移，并覆盖“终点正常但中间经过塌缩”的情形。

窄眼测试图的组合转头仍保留人物动作，远处棋盘背景像素最大差为 **0**；睁眼图层重组与原图的像素最大差为 **0**，完全闭眼时两眼均无暴露的白色眼白。开口随四分之一、一半、全部输入连续增大，没有添加白色牙齿。

这些数字描述固定测试输入，不能证明所有画风和所有定位结果都没有畸变。单图没有侧面信息，网格保护会在必要时减少位移；它不会生成遮挡处的新画面。

## 已运行检查

`python tools/check_avatar.py --browser --browser-path <Chromium>` 共执行 17 组：

- 10 组 Node 单元/集成检查：模型、跟踪、UI 状态机、网格与角色文件、KalidoKit 映射、嘴部响应、风格库、单图绑定、输出设置、位移保护。
- 13 项 Python 服务测试：静态页与缓存、接口错误、风格文件、图片格式及 gzip 等。
- 6 组真实浏览器检查：像素与背景、生成到绑定到摄像头、缓存恢复、精细编辑与设置保存、旧角色与 WebGL 降级、生图页上传/拍照/24 风格与历史。

额外检查了放大图拖动的坐标、两个导出入口的未应用状态、导入角色微调后再次导出、快速停止/开启摄像头及旧推理结果隔离。

浏览器使用 Chromium 与软件 WebGL 执行；不把测试机的帧率当作用户电脑的性能指标。需要在真实摄像头下进一步观察镜片反光、侧脸遮挡、说话时嘴唇拟合，以及不同卡通画风的定位质量。

## 操作和回退

更新后按 Ctrl+F5，选回原图并重新确认一次绑定。微调可以“恢复推荐值”，误改区域可以撤销；“恢复插画示例”会清除自动恢复的图片选择。恢复旧 `.mavatar` 不会抹掉图库中的生成图。

[8 秒演示](portrait-v11-preview.webm) 为真实渲染器输出，使用仓库自有插画，未经生图模型重新生成；正常网页使用不需要 Playwright 或 FFmpeg。
